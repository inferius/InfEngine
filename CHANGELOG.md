# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- Editor asset browser (Phase 9.5): a new collapsing "Assets" section lists every file under the project's asset root, recursive + sorted, with a Refresh button to rescan.
- `docs/editor-guide.md` covering quickstart, project model, inspector sections, viewport controls, the undo/redo behaviour, and the Export flow. Linked from README's roadmap entry.
- New crate `infengine_runtime` + Export pipeline (Phase 9.4): `infengine_runtime` is a standalone bin that loads `project.ron`, opens the first scene, and renders it with WASD/QE camera controls. The editor's new "Export -> dist/" button copies the project manifest, every scene file, and the asset directory into a `dist/` folder next to `project.ron` and writes a `README.txt` with build instructions for the runtime binary. End-state for a shipped game: `cargo build --release -p infengine_runtime` + copy the binary next to `dist/`.
- Editor 2D translate gizmo (Phase 9.3): axis-locked translate handles render via the debug overlay around the selected entity. Red arm = X axis, green arm = Y axis, yellow center square = free drag. Picking respects gizmo priority over body pick. Once a handle is grabbed, drag only modifies the chosen axis (Free / X / Y). 3D translate gizmos arrive once the editor renders 3D scenes.
- Editor undo / redo (Phase 9.2): snapshot-based history of the whole `Scene`, ring-buffered at 64 entries. Snapshots are pushed before any structural change (drag-start, add entity, remove entity). Keyboard: `Ctrl+Z` undo, `Ctrl+Y` or `Ctrl+Shift+Z` redo. Toolbar buttons in the inspector show the current stack depths.
- New crate `infengine_editor_app` with a standalone `editor_app` binary (Phase 9.1): takes an optional `project.ron` path on the command line (creates one if missing), loads the project manifest, and presents a scene picker, hierarchy, and selection inspector. Mouse picking + drag, log-scaled zoom (Q/E), scene save / project save / new-scene buttons, add-entity buttons, region picker, color edits, scale + position drag values.
- `infengine_core::project::Project` with serde RON serialization, asset-root resolution helpers, and a unit test for round-tripping. Adds `ProjectError` and a `ProjectScene { name, path }` entry.
- C# OnTick + scripted player (Phase 8.4 / 8.6): `EngineApi` grows `get_player_pos` / `set_player_pos`; a thread-local `FrameContext` carries player position across the FFI boundary. Managed `Engine.GetPlayerPos` / `SetPlayerPos` + a new `Player.OnTick(float dt)` script drives the selected entity on a figure-eight. `sprite_demo` auto-loads the assembly when present, registers the API, calls `Player.OnTick` every frame, and surfaces a toggle in a new "Scripting (C#)" inspector section.
- Rust <-> C# bindings (Phase 8.3): a `#[repr(C)]` `EngineApi` struct of `extern "C"` function pointers (`log_info`, `time_secs`) plus a `default_engine_api()` builder. Managed side mirrors the struct as `EngineApiPtrs` and exposes a `Engine` static facade (`Engine.Log(string)`, `Engine.TimeSeconds()`). `ScriptAssembly::get_fn_register_api` resolves `Engine.RegisterApi(EngineApiPtrs*)` so the host can push the table into C# at startup.
- `Hello.EngineRoundTrip()` C# method logs back through Rust's tracing pipeline using `Engine.Log`, proving the bidirectional FFI works.
- New crate `infengine_scripting` (Phase 8.1-8.2): wraps the `netcorehost` 0.18 crate to bootstrap an in-process .NET 10 runtime via `hostfxr`. `ScriptHost::new(runtime_config)` loads `hostfxr`, initializes a runtime, and exposes `load_assembly(path) -> ScriptAssembly`. `ScriptAssembly::get_fn_void` / `get_fn_int` resolve C# methods marked `[UnmanagedCallersOnly]` to callable function pointers.
- Sample C# project `scripts/InfEngine.Scripts` (TFM `net10.0`, latest LangVersion) with `Hello.HelloFromCSharp()` and `Hello.LifeUniverseEverything()` entry points.
- New example `examples/csharp_demo`: builds `InfEngine.Scripts.dll`, loads it, invokes both entry points, prints `Hello from C# 10.0.7!` and the returned `42`. End-to-end verified with `dotnet build -c Release` + `cargo run -p csharp_demo`.
- Workspace pin `netcorehost = "0.18"` and a new workspace member entry.
- `.gitignore`: exclude `/scripts/**/bin/` and `/scripts/**/obj/` from git.
- `infengine_physics::three` + `PhysicsWorld3D` (Phase 7.1): rapier3d wrapper exposing a handle-based API (`create_body(BodyDesc)`, `step(dt)`, `translation(id)`, `rotation(id)`, `set_translation`). `BodyKind3D` covers Dynamic / Static / Kinematic; `ColliderShape3D` covers Box / Sphere / Capsule. Gravity defaults to `(0, -9.81, 0)` and is settable. Scene-driven integration arrives once the engine's `Scene` model gains 3D entities.
- `cube_demo` spawns a 6-cube stack + 4 bouncing balls on a static ground bar to the right of the rotating ring. `R` rebuilds the world. Cubes and balls inherit per-instance PBR materials so they show on-impact behaviour with varying metallic / roughness.
- PBR baseline shading (Phase 6.4): `MeshInstance` now carries `(metallic, roughness)` material parameters; the mesh shader replaces the simple Lambert with a Cook-Torrance specular (GGX distribution, Schlick Fresnel, smith-GGX geometry) plus a Lambert diffuse term and a hemispheric ambient. F0 lerps from 0.04 dielectric to the albedo for metals. New `Renderer::draw_mesh_pbr(handle, model, color, metallic, roughness)` and `MeshInstance::with_material` helpers.
- `cube_demo` cycles metallic + roughness across the ring cubes and renders the bouncing sphere as chrome (metallic 1.0, roughness 0.15) to exercise the new shading path.
- glTF 2.0 loader (Phase 6.3): `AssetServer::load_gltf(path)` parses .gltf / .glb files via the `gltf` crate and returns a `GltfAsset` with one `GltfPrimitive` per primitive (positions, normals defaulted to `[0, 1, 0]`, UVs defaulted to `[0, 0]`, indices synthesized for non-indexed primitives). New `AssetError::Gltf` variant. Workspace pins `gltf = "1"`.
- `cube_demo` loads `assets/model.glb` if present; each primitive becomes a registered renderer mesh and draws next to the cubes / spheres. Without a file the demo logs a hint and runs unchanged.
- Mesh registry (Phase 6.2): `MeshVertex`, `MeshHandle`, and a `Mesh3DRegistry` keyed by handle. `Renderer::create_mesh(name, vertices, indices)` registers an arbitrary mesh; `Renderer::draw_mesh(handle, model, color)` queues an instance. The pipeline groups the per-frame queue by handle and emits one batched indexed draw per mesh. The built-in cube is now just one registered mesh; its handle is available via `Renderer::cube_handle()`.
- `cube_demo` generates a UV sphere (24x32 segments) procedurally on startup and uses `draw_mesh` to render a bouncing sphere over the pillar plus three smaller spheres orbiting it.
- 3D rendering pipeline (Phase 6.1): new `Camera3D` (right-handed perspective with position / target / up / fov / aspect / near / far) and a built-in batched cube mesh. `Renderer::draw_cube(model, color)` queues a per-instance 4x4 column-major matrix + tint; the pipeline runs in its own pass with a `Depth32Float` depth attachment so cubes self-occlude. Shader does a flat directional-light shade (ambient + Lambert) for visual readability. Per-frame `Renderer::render` now runs the 3D pass first (clearing the surface + depth) followed by the existing 2D / debug / egui passes on top.
- `examples/cube_demo`: orbit-camera demo with a ground plate, five rotating ringed cubes, and a central pillar. WASD orbits / raises the camera; Q / E zoom; Esc exits.
- `infengine_audio` gains disk-loaded sounds (Phase 5.7): `AudioSystem::load_sound(path)` returns a cloneable `Sound` (wrapping `kira::StaticSoundData`) loaded via kira / symphonia (WAV / OGG / FLAC / MP3). `AudioSystem::play_sound(&Sound)` plays a one-shot. New `AudioError::LoadFile` variant.
- `sprite_demo` synthesizes `assets/chime.wav` on first run (two-tone PCM with a linear envelope, written via a hand-rolled WAV writer), loads it through `AudioSystem::load_sound`, and plays it on the `C` key alongside the existing synthesized `Space` beep.
- New crate `infengine_physics` (Phase 5.6): wraps `rapier2d` behind a `PhysicsWorld` that consumes the engine's `Scene` model. `rebuild` re-creates rigid bodies and colliders from every entity that carries a `PhysicsComponent`; `step` advances the simulation (`dt` clamped to 50 ms); `write_back` copies world translations into `Transform2D` for the renderer; `sync_from_scene` pushes editor edits into the active bodies between rebuilds.
- `infengine_core::scene` gains `BodyKind` (`Dynamic`, `Static`, `Kinematic`), `ColliderShape` (`Box`, `Circle { radius }`), and a `PhysicsComponent { body, shape, linear_damping, restitution, friction }`. `Scene::gravity` is a new persisted field (default `[0, -1200]`).
- `sprite_demo` default scene gains a ground bar plus physics components on player, orbs (one circle, one box), and the ground. A "Play" / "Stop" button in the inspector enters / leaves simulation mode; entering Play snapshots the scene and rebuilds the world, Stop restores the snapshot.
- `sprite_demo` is now scene-driven (Phase 5.2): on first run the demo writes a default 3-entity scene (`player` + two `orb` decorations) to `assets/scene.ron`; subsequent runs load it. Editor side panel adds a "Scene" section with Save / Load / Reset buttons plus the background color picker. The Selection subpanel edits the currently selected entity's name, transform (X / Y / Scale), and sprite (size / color / atlas region via a `ComboBox`); WASD / arrows move the selection rather than a hard-coded player. Camera follow targets the selected entity.
- `infengine_core::scene` (Phase 5.1): a small serializable scene model. `Scene` owns an ordered `Vec<Entity>`, a stable `next_id` counter, a name, and a clear color; `Entity` carries an `EntityId`, a name, a `Transform2D`, and an optional `SpriteComponent` with `(size, color, AtlasRegion)`. `AtlasRegion` is an enum (`Full`, `Checker`, `Dots`, `Stripes`, `Cross`) and exposes `uv_rect()` matching the renderer's atlas layout. `Scene::load` / `save` round-trip through RON files with pretty-printing.
- `sprite_demo` inspector panel (Phase 4.2): a resizable left side panel with collapsing sections for Camera (follow toggle + zoom slider), Player (position sliders clamped to the tilemap, size slider, RGBA color picker), and World (background color picker, debug-overlay toggle). All edits update the running scene in real time and exercise `Renderer::camera_mut`, `set_clear_color`, the sprite tint pipeline, and the debug overlay's toggle path.
- New crate `infengine_editor` (Phase 4.1): wraps `egui` 0.33, `egui-wgpu`, and `egui-winit` behind an `EditorUi` type. `EditorUi::new`, `handle_window_event`, `run(window, |ctx| ...)`, and `render(...)` are the four-method API engine code uses.
- `infengine_window` exposes `pub use winit as raw_winit` and a new `AppHandler::on_window_event(&EngineWindow, &WindowEvent)` hook so the editor can forward raw input. Documented as a deliberate ADR-0001 carve-out for editor-level integrations.
- `infengine_render::Renderer` exposes `wgpu_device`, `wgpu_queue`, and `surface_format` accessors so workspace-internal crates can build extra pipelines against the same logical device.
- `Renderer::render` now takes an `overlay` closure that receives `(device, queue, encoder, view, physical_size)` after the world pass; the demo passes `editor.render(...)` to draw the egui UI on top of the world.
- `sprite_demo` replaces the bitmap HUD with an egui window showing FPS, position, zoom, queued sprite count, asset reloads, beep count, and controls. Bumped `wgpu` to 27 to match `egui-wgpu` 0.33.
- New crate `infengine_audio` (Phase 3.3): wraps `kira` 0.10 with an `AudioSystem` that initializes the default backend and exposes `play_beep(freq_hz, duration_secs, volume)`. Synthesizes a sine-wave tone with 5 ms fade in / out and submits it to `kira` as a `StaticSoundData`. `AudioError` covers backend init and play failures.
- `sprite_demo` initializes the audio system at startup and plays a 440 Hz, 100 ms beep on each Space-key press; the HUD shows a running `BEEPS` counter alongside `RELOADS`.
- `infengine_assets` hot reload (Phase 3.2): `AssetServer::watch()` returns an `AssetWatcher` whose `receiver` yields `AssetEvent::Modified(path)` and `Removed(path)` over a `std::sync::mpsc::Receiver`. Paths are emitted relative to the asset root. `AssetServer::handle_path(handle)` reverse-resolves a handle back to its source path so callers can decide when to call `reload_image`. The underlying watcher uses `notify::RecommendedWatcher` and stops when the `AssetWatcher` is dropped.
- `sprite_demo` polls hot-reload events each frame, reloads `sample.png` when modified, and shows the running reload count on the HUD.
- `infengine_assets::AssetServer`, `AssetHandle<T>`, and `ImageAsset` (Phase 3.1): typed handles backed by a numeric `AssetId`, a `RwLock`-guarded cache, and PNG/JPG/WebP decoding via the `image` crate. `AssetServer::load_image` returns a cached `Arc<ImageAsset>` and rejects paths that try to escape the asset root.
- `AssetServer::reload_image` re-decodes a previously loaded image from disk; used by Phase 3.2 hot reload.
- `sprite_demo` auto-generates `assets/sample.png` on first run and loads it through the `AssetServer` to exercise the load path end-to-end.
- Debug-line overlay (Phase 2.7): a second `wgpu` pipeline with `LineList` topology renders colored line segments in world space on top of the sprite pass. Vertex format is `position (vec2) + color (vec4)` and the GPU buffer grows dynamically just like the sprite instance buffer. `Renderer::debug_line`, `debug_rect`, and `debug_circle(center, radius, color, segments)` queue diagnostics that auto-clear at the end of each `render()`.
- Bitmap text rendering (Phase 2.6): a hand-rolled 5x7 ASCII bitmap font is packed into the bottom strip of the sprite atlas (16x6 8x8 cells). `Renderer::draw_text(text, position, pixel_size, color)` queues one `SpriteInstance` per character, sharing the existing batched sprite pipeline so HUD text costs no extra draw calls. Supports digits, uppercase A-Z, and common punctuation; unsupported codepoints render blank. Decision recorded for future replacement by `cosmic-text` once the asset pipeline lands.
- Phase 2.5: `sprite_demo` now drives the camera each frame. The player walks across a 40x30 tilemap, the camera follows the player's world position, and `Q` / `E` zoom out / in via an exponential rate (clamped to `[0.25, 4.0]`). Demonstrates `Camera2D::position` / `zoom` mutation through `Renderer::camera_mut`.
- `infengine_render::Tilemap` and `TileId` (Phase 2.4): grid-based tilemap with a world-space origin, uniform tile size, and a `TileId::EMPTY` sentinel for skipped cells. `Renderer::draw_tilemap` expands each non-empty tile into a `SpriteInstance` and queues it into the existing sprite batch, so a tilemap costs zero extra draw calls. Demo: 24x14 tilemap (336 tiles), 4 decorations, and a player all render in one draw call.
- `infengine_render::demo_atlas` (Phase 2.3): procedurally generated 256x256 four-quadrant texture atlas (`CHECKER`, `DOTS`, `STRIPES`, `CROSS`) plus matching UV sub-rectangle constants. The atlas replaces the previous single-quadrant checker; the existing `SpriteInstance` UV fields drive the sub-rectangle selection. Marked as temporary - retires when the real asset pipeline arrives in Phase 3.
- `SpriteInstance::from_region(position, size, region)` and `SpriteInstance::with_color(color)` helpers so callers can pick an atlas region without manipulating UVs directly.
- `infengine_render::SpriteInstance` and `Renderer::draw_sprite` (Phase 2.2): batched per-instance sprite rendering. Each instance carries a world-space `position`, a `size`, an RGBA color tint, and a UV sub-rectangle (`uv_min` / `uv_max`) so that future atlases work without shader changes. The sprite pipeline now consumes a dynamic instance buffer that grows in power-of-two steps starting from a capacity of 256; one draw call renders every queued instance.
- `infengine_render::Camera2D` (Phase 2.1): orthographic 2D camera with `position`, `zoom`, and viewport size. World-space coordinates use 1 unit = 1 logical pixel at zoom 1.0; `Renderer::camera_mut` exposes it for pan/zoom in later steps.
- `infengine_render::camera::CameraResource` (internal): camera uniform buffer + bind group, bound at `@group(0)` and uploaded once per frame inside `Renderer::render`.
- `infengine_window::InputState` and `FrameContext` (Phase 1.4): the engine tracks pressed keys via the `Key` enum and exposes a per-frame snapshot plus a `delta_time` (seconds) to `AppHandler::on_update`. Focus loss clears the input state to avoid stuck keys.
- `sprite_demo` (Phase 1.4): WASD or arrow keys move the sprite at 1.4 NDC units/sec (frame-rate independent), `R` recenters, motion clamps to the screen. Diagonal motion is normalized so it isn't faster than axis-aligned motion.
- `infengine_render::sprite` (Phase 1.3): textured-quad pipeline with a packed `position + uv` vertex format, a `vec4` transform UBO (offset_xy + scale_xy), bind group covering uniform + texture + sampler, and a procedurally generated 128x128 checkerboard sRGB texture uploaded via `queue.write_texture`. Pipeline uses `TriangleStrip` with `ALPHA_BLENDING` so transparent sprites remain composable later. Exposed through `Renderer::set_sprite_transform`.

### Changed
- `Renderer::set_sprite_transform` was removed; callers now submit one `SpriteInstance` per visible sprite per frame via `Renderer::draw_sprite`. The internal queue is cleared after every `render()` call.
- `infengine_render::sprite` (Phase 2.1): the sprite pipeline now uses two bind groups - camera at `@group(0)` and the texture + sampler at `@group(1)`. The per-sprite transform moved from a uniform into the instance buffer.
- `AppHandler::on_update` now takes `&FrameContext<'_>` in addition to the `EngineWindow`, surfacing `delta_time` and the current `InputState` to application code.
- `infengine_render`: minimal wgpu-backed `Renderer` (Phase 1.2) that owns an `Instance`, `Surface`, `Device`, and `Queue`, configures an sRGB swapchain with `AutoVsync` present mode, and clears the framebuffer to a solid color every frame. Recovers from `Lost` / `Outdated` surface errors by reconfiguring.
- `infengine_window`: minimal winit-based event loop wrapping `EngineWindow`, `AppHandler` trait, and an engine-side `Key` enum that does not leak winit types.
- `examples/sprite_demo`: Phase 1.2 proof of concept - opens a window, initializes the wgpu renderer, presents a vsynced cleared frame every tick, and exits on Escape.
- Initial Cargo workspace with `infengine_core`, `infengine_window`, `infengine_render`, and `infengine_assets` crate placeholders.
- Dual MIT / Apache-2.0 licensing.
- GitHub Actions CI matrix for Windows and Linux on stable Rust.
